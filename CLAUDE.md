# Working in this repo

Always use the `coding-guidelines` skill for any code change, review or plan:

- Think before coding: state assumptions, and ask when a request can be read more than one way.
- Simplicity first: the minimum code that solves the request, nothing speculative.
- Surgical changes: every changed line traces to the request; mention unrelated issues instead of fixing them.
- Goal-driven: define how success is checked, and verify before calling work done.
